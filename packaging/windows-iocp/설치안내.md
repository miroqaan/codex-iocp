# Codex IOCP 패치 설치 안내

이 문서는 다른 Windows PC에 패치를 설치하는 사람을 위한 순서별 안내입니다.

## 1. 적용 가능한 PC인지 확인

| 항목 | 필요한 조건 |
|---|---|
| 운영체제 | Windows x64 |
| 기존 앱 | Microsoft Store/MSIX Codex가 설치되어 있어야 함 |
| Codex 앱 버전 | **26.908.4834.0** |
| 백엔드 버전 | **0.154.0-alpha.6.2** |
| 관리자 권한 | 불필요 |

설치 프로그램이 검증된 앱·엔진 조합 허용 목록과 파일 해시를 자동 검사합니다. 현재 등록된 조합은 위 버전 하나이며, 목록에 없거나 파일 해시가 다르면 설치하지 않습니다. 이 ZIP은 Codex 앱 전체 설치 파일이 아니라, 기존 앱에 연결할 수정 백엔드와 설치 도구입니다. ARM64·macOS·Linux 및 독립 CLI만 설치된 PC에는 적용하지 않습니다.

버전을 먼저 확인하려면 Windows PowerShell에서 다음을 실행합니다.

```powershell
Get-AppxPackage -Name OpenAI.Codex | Select-Object Name, Version, Architecture
```

출력이 없으면 해당 사용자에게 Codex 앱이 설치되어 있지 않은 것입니다. 다른 버전이 나오면 해당 앱·엔진 조합의 호환성 검증과 허용 목록 갱신이 필요합니다.

## 2. 파일을 옮기고 압축 해제

1. `Codex-IOCP-Patch-0.154.0-alpha.6.2-win-x64.zip`을 대상 PC로 복사합니다.
2. ZIP을 오른쪽 클릭해 **모두 압축 풀기**를 실행합니다.
3. 압축을 푼 폴더 안의 `Codex-IOCP-Patch` 폴더를 엽니다.
4. `Install.cmd`, `Install.ps1`, `Launch.ps1`, `Uninstall.ps1`, `manifest.json`, `payload` 폴더가 함께 있는지 확인합니다.

ZIP 내부에서 직접 설치하지 마세요. `Install.cmd`만 따로 복사해도 설치할 수 없습니다.

## 3. 설치

1. Codex에서 진행 중인 작업을 마무리합니다.
2. Codex 앱을 완전히 종료합니다.
3. 압축 해제한 폴더의 **`Install.cmd`를 더블클릭**합니다. 관리자 권한으로 실행할 필요가 없습니다.
4. 표시되는 결과를 확인합니다.

성공하면 다음 형태의 두 줄이 표시됩니다.

```text
Installed: C:\Users\사용자이름\AppData\Local\CodexIocpPatch\b5bffd3e
Shortcut: ...\Desktop\Codex (IOCP Patch).lnk
```

바탕화면에 **`Codex (IOCP Patch)`** 바로가기가 생겼으면 설치가 완료된 것입니다. 안내에 따라 키를 눌러 설치 창을 닫습니다. 설치 프로그램은 앱을 자동 실행하지 않습니다.

`Installation failed. Read the error above.`가 나오면 실패입니다. 그 위에 표시된 실제 오류를 확인하고 아래 오류 안내를 참고하세요.

## 4. 패치 버전 실행 및 확인

1. 바탕화면의 **`Codex (IOCP Patch)`**를 실행합니다.
2. 기존 Codex 화면이 열리는지 확인합니다. 필요한 경우 대상 PC의 계정으로 로그인합니다.
3. 모델 목록과 MCP 상태가 정상적으로 표시되는지 확인합니다.

**앞으로도 이 전용 바로가기로 실행해야 합니다.** 기존 공식 바로가기는 원본 백엔드로 실행합니다. 기존 앱이 남아 있으면 패치 실행은 오류 메시지와 함께 중단되므로 앱을 완전히 종료한 뒤 다시 실행합니다.

정확한 백엔드 경로를 확인하려면 PowerShell에서 실행합니다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='codex.exe'" |
    Select-Object ProcessId, ExecutablePath
```

패치 앱의 백엔드 경로에 `\CodexIocpPatch\b5bffd3e\codex.exe`가 포함되어 있어야 합니다. 다른 CLI를 함께 사용하면 codex.exe가 여러 개 보일 수 있습니다.

## 5. 오류가 날 때

| 메시지·상황 | 확인할 내용 |
|---|---|
| 승인된 조합을 찾을 수 없다는 메시지 | 현재 앱·엔진 조합이 허용 목록에 없음. 호환성 검증 후 목록이 갱신된 패키지를 준비. 공식 바로가기 사용 시 IOCP 패치는 적용되지 않음 |
| `SHA256 mismatch` | 파일 손상·누락·변경 또는 공식 파일 불일치. 원래 ZIP을 다시 복사해 전부 압축 해제하고 재검사 |
| `Install directory already exists` | 이미 설치했거나 이전 설치 흔적이 있음. 해당 폴더의 설치 상태부터 확인; 덮어쓰지 않음 |
| `Shortcut already exists` | 같은 이름의 바로가기가 있음. 연결 대상을 확인한 뒤 이전 패치 원복 절차 사용 |
| `Codex desktop is still running` | 기존 Codex를 완전히 종료한 뒤 전용 바로가기 재실행 |
| `This patch is disabled` | 원복했거나 설치 도중 실패한 폴더임. 공식 바로가기 사용 후 설치 기록 확인 |
| 바로가기 실행 오류 | 아래 로그 파일 확인 |

실행 오류 로그는 `%LOCALAPPDATA%\CodexIocpPatch\b5bffd3e\launch-error.txt`입니다. Windows 탐색기 주소창에 `%LOCALAPPDATA%\CodexIocpPatch\b5bffd3e`를 입력하면 설치 폴더를 열 수 있습니다.

이 패키지는 OpenAI 서명이 없는 로컬 수정 빌드입니다. 조직 정책이나 보안 제품이 실행을 막는 경우 표시된 차단 원인을 확인하세요. 보안 기능을 일괄 해제하는 절차는 설치에 포함되어 있지 않습니다.

설치 전 검사만 하려면 압축 해제한 폴더에서 PowerShell을 열고 실행합니다. 파일이나 바로가기를 만들지 않습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -CheckOnly
```

## 6. 원래 Codex로 되돌리기

1. 진행 중인 작업을 마무리하고 Codex를 완전히 종료합니다.
2. Windows PowerShell에서 다음을 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\CodexIocpPatch\b5bffd3e\Uninstall.ps1"
```

3. 패치가 비활성화되고 이 설치가 만든 바로가기가 제거됩니다.
4. **기존 공식 Codex 바로가기**로 실행합니다.

원복은 공식 앱·대화·로그인·개인 설정을 삭제하지 않습니다. 패치 파일과 기록은 설치 폴더에 남습니다. 패치 앱을 완전히 종료한 뒤 불필요하면 해당 설치 폴더만 수동 삭제할 수 있습니다. 다시 설치하려면 기존 설치 폴더와 바로가기 잔여 여부를 먼저 확인합니다.

## 7. Codex 업데이트 후

이 패키지는 **Microsoft Store 자동 업데이트를 차단하지 않습니다.** 공식 앱이 업데이트되어 검증된 조합 허용 목록에 없으면 패치 실행기를 중단합니다. 공식 바로가기로는 사용할 수 있지만 IOCP 패치 엔진은 적용되지 않습니다.

관리자는 `manifest.json`의 `schemaVersion: 2`와 `approvedCombinations`를 관리합니다. 각 항목은 정확한 앱 `packageFullName`, 엔진 `backendVersion`, 패치 바이너리 `patchedSha256`, 원본 파일 `officialArtifacts`의 SHA-256으로 조합을 지정합니다. 현재는 앱 `26.908.4834.0`과 엔진 `0.154.0-alpha.6.2`만 승인되어 있습니다.

새 공식 앱에서 기존 패치 엔진과 보조 파일의 호환성을 실제로 검증한 뒤 조합을 추가하고 패키지를 갱신합니다. 기존 엔진을 사용할 수 있으면 Rust 재빌드는 필요 없으며 스크립트·manifest 갱신과 ZIP 재포장으로 충분합니다. 새 엔진이 필요할 때만 IOCP 패치를 이식해 빌드·회귀 테스트·실제 앱 연결을 검증합니다. 버전 검사 제거, 검증 없는 목록 추가, 다른 조합의 실행 파일 혼용은 하지 마세요.

이 패치는 확인한 Windows MCP 파이프 스레드 고갈 원인을 수정합니다. 모든 종류의 멈춤을 보장하지는 않습니다. 원리·검증 범위는 `README.md`, 소스 재빌드는 `source/BUILD.md`를 참고하세요.
